# Reth v2.4.1 Dependency-Only Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Alethia Reth on `main` to the exact Reth v2.4.1 dependency stack while preserving Taiko behavior and excluding JIT.

**Architecture:** All direct Reth crates and the vendored Optimism trie share one Reth git revision. Compatibility changes stay at the existing consensus, execution, payload, RPC, and proof-history adapters, with explicit fail-closed handling for unsupported Amsterdam fields.

**Tech Stack:** Rust 1.95, Cargo workspace, Reth v2.4.1, Alloy 2.1.1/1.6.1, alloy-evm 0.37, revm 41, cargo-nextest.

## Global Constraints

- Pin every direct `paradigmxyz/reth` git dependency to `8eb210175687c9f0c889a3b6795c16781d830e3a`.
- Use Alloy API crates `2.1.1`, `alloy-primitives`/`alloy-sol-types` `1.6.1`, `alloy-evm` `0.37.0`, and `alloy-rlp` `0.3.16`.
- Require `reth-codecs` and `reth-primitives-traits` `0.5.0`, resolving to `0.5.2` in `Cargo.lock`.
- Use `revm-database-interface` `41.0.0` and Rust `1.95.0`.
- Vendor `reth-optimism-trie` from Optimism commit `4f21ce6b9574ffc3473dd3b622ec9f7bd0c72fad`.
- Enable Reth's existing non-JIT defaults explicitly and retain `reth-revm/portable`; never enable Reth's `jit` feature.
- Do not add direct `revmc` dependencies, LLVM provisioning, JIT controls, JIT wrappers, or JIT tests.
- Preserve Taiko fork selection, zk-gas accounting/truncation, anchor execution, base-fee sharing, payload behavior, RPC behavior, and proof-history semantics.
- Reject Amsterdam activation, EIP-7928 block access lists, slot numbers, and unsupported engine fields.
- Document every non-test production Rust symbol added or changed, including trait implementation methods.
- Before opening the PR, remove the entire `docs/superpowers` directory from the branch.
